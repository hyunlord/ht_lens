## 4. 휴리스틱 신뢰도 평가

### ✗ 파일 크기 — 불충분
- 열화: 5328 / 5341 / 9798B. 정상 소형: 게임 스크린샷(7–11KB), 인물 사진(10KB), **완전한 흰 배경 다이어그램**(ch55 10532B, ch3073 11122B, ch3020 14884B).
- <10KB 컷은 false positive 다수 → 단독 사용 불가.

### ✓ 검은 배경 픽셀 비율 — 신뢰 가능
(64×64 축소 후 luminance<40 비율)

| 그룹 | 값 |

| 열화 (ch1/84/85) | **0.92 / 0.89 / 0.76** |
| 정상 최대 | 0.45 (ch538 어두운 인물 사진) |

→ **임계값 0.6이면 3/3 검출, false positive 0** (마진 0.76 vs 0.45). 깔끔한 자동 검출기.

**한계**: 이 휴리스틱은 "검은 배경 임베디드 래스터" 아티팩트에 특화. 만약 흰 배경 임베디드 래스터로 열화된 figure가 있으면 놓침(이 코퍼스엔 없음). 향후 docs엔 더 견고한 검출(= MinerU 크롭 vs 페이지-크롭 유사도 비교, 메커니즘 무관)이 안전.

## 5. 페이지-크롭 복구 가능성 (실증)

- **ch1 (Fig 28.17)**: middle.json bbox [242,59,343,203] (page_size 576×648) 기준 page_0000.png 크롭 → **완전한 DPGM 다이어그램** (앞선 진단).
- **ch84 (Fig 28.23a)**: bbox [161,58,226,204] 기준 page_0008.png 크롭 → **완전한 LDA PGM 다이어그램** (α→z_n→c→x→W→β, "(a)") 복구.
- **두 케이스 모두 페이지-크롭이 손실 없이 완전 복구.** 수정 경로 유효.

**좌표 주의 (수정 시 필수)**:
- DB `bbox_json`은 MinerU **content_list** bbox = ~1000 캔버스로 **비균일 정규화**(x≈×1.735, y≈×1.542). 페이지 렌더와 직접 정렬 불가.
- 정렬에는 **middle.json bbox + page_size** 필요. doc1은 전 페이지 [576,648]로 일관하나, **doc마다 page_size 다를 수 있어** 수정 구현 시 doc/page별로 읽어야 함.
- 라벨이 임베디드-래스터 bbox 밖으로 약간 나가므로 **패딩(~20px) 필요** (실증에서 적용).

## 6. 권고 — (b) 선별 수정

| 기준 | 평가 |
|------|------|
| 범위 | 극소 (3/161 = 1.9%, **단일 doc**; 논문 3종+교재 0건) |
| 검출기 | 신뢰 가능 (검은 배경 비율 >0.6, 마진 큼) |
| 무회귀 | 정상 158개(matplotlib 고해상·사진·완전 다이어그램) 그대로 보존 |
| 비용 | 낮음 (3개만 페이지-크롭) |

**→ (b) 선별 수정 권고.** 검출기로 열화 chunk만 골라 페이지-렌더 bbox 크롭으로 서빙(또는 재추출). 정상 figure는 MinerU 크롭 유지.

**(a) 전 figure 통일**도 가능하나 비권고: (1) 159개 정상에 불필요, (2) 일부 matplotlib 임베디드 래스터는 페이지-크롭보다 고해상, (3) 어느 쪽이든 middle.json 좌표 plumbing은 동일하게 필요하므로 (a)의 "단순함" 이점이 상쇄됨.

**수정의 핵심 선행조건 (별도 phase)**: ingest 시 middle.json bbox+page_size를 보존(또는 재계산)하는 경로 — 현재 DB엔 페이지-크롭에 못 쓰는 content_list bbox만 있음.
